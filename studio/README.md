# 剧本工作台

在项目根目录双击 `启动剧本工作台.bat`，打开 http://127.0.0.1:5174/studio/ 。窗口需保持运行。旧探索广场的「创作」也已链接到工作台；如果旧服务正在运行，重启后才会加载新增接口。

## 试玩《转生史莱姆 · 森林来信》

这是基于《关于我转生变成史莱姆这档事》基本世界观创作的非官方同人支线。玩家是另一只刚转生的史莱姆；洛可、灰苔聚落和溪谷事件为原创，不是小说章节改写。

1. 输入称呼，选择感知、交涉或探索天赋，然后在森林中醒来。
2. 默认离线试玩，点击行动选项即可完成四次行动的序章。分析、交涉、探索会产生不同文本、消耗、物品和记忆。此模式是预写分支，不是自由生成；自由输入会按关键词归类为三条路线。
3. 在「模型连接」中选择 AI 冒险，填写兼容 chat/completions 的基础地址、模型名称及自己的密钥，就可以继续自由行动。请求采用整段生成，需要模型能够遵循 JSON 输出要求。
4. 右侧显示生命、魔力、目标、物品和重要记忆。两套阅读皮肤随存档保存。
5. 自动保存状态显示在输入框下方。刷新后，从左侧存档列表选择继续。保存失败时可重试，或导出 JSON 备份。

## 编辑

「编辑剧本」支持名称、简介、提示词、前后置词、开场正文与世界书。保存后重新开局生效；已有存档保存独立的剧本快照。可另存副本、导入或导出剧本 JSON。

世界书格式：

```json
[{"name":"地点资料","keys":["营地","守卫"],"depth":4,"content":"该地点的背景设定。"}]
```

`depth` 指回看消息条数（1–20），并同时检查当前行动。关键词按「或」匹配。本版没有原站完整的多作用域与插入优先级编辑器。原始用户／AI 消息保留在存档中；发送时带最近最多12条历史消息、最近状态和累计记忆。累计记忆由模型更新，不是独立摘要模型。

## 文件和边界

- `slime.json`：可编辑的种子剧本，首次启动加入 SQLite，后续不会覆盖数据库中的修改。
- `intro.html`：独立开局页，在不允许同源访问和网络请求的脚本沙箱中运行；通过经过来源、消息类型和随机通道检查的消息提交角色配置。
- `engine.js`：世界书匹配、上下文组装、回复验证和离线分支。
- `app.js`：编辑器、阅读器、模型调用和存档界面。正文按文本渲染，不执行模型返回的 HTML。
- `studio_api.py`：新增 `studio_decks`、`studio_saves` 表，沿用 `noval_data.db`。不改写旧存档。

当前是本地工作台，未实现任意作者 HTML/CSS 上传、正则规则编辑器、公开发布、账户体系或模型流式输出。AI 模式需要用户提供有效连接，测试没有消耗任何外部模型额度。密钥仅保存在当前页面内存，刷新后需重新填写。

## 验证

项目根目录运行 `python -m unittest test_studio -v`（临时数据库）；运行 `node studio/test_engine.cjs` 检查三条离线路线、上下文和响应校验。浏览器交互尚需实际试玩验收。
