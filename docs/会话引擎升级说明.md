# 会话引擎升级说明

## 使用入口

- 首页「我的角色卡」：导入酒馆 V2 / V3、普通角色卡 JSON、PNG，以及本站会话备份；登录后可上传私人云端、下载云端版本和使用回收站。
- 聊天页顶部「会话工作台」或输入框上方「会话设置」：玩法、剧情分支、记忆与状态、状态规则、世界书、正则、扩展、视听、提示词检查。
- 设置需要点击「应用并保存」。没有消息的新会话在发送第一条消息时开始保存。

## 本轮完成

1. 新的通用会话引擎替代聊天入口中按剧本硬编码的提示词拼接。角色身份、场景、对话示例仍取自剧本数据。旧提示词模块保留，便于逐个迁移旧剧本。
2. 自由聊天、小说叙事、规则冒险三种玩法；可配置节奏、篇幅、行动选项数量（0–4）、玩家称呼及叙事要求。不再改写玩家输入以强制转场。
3. 按输入预算选择连续的最近历史，预留回复和额外余量。中文采用保守估算，不是模型专用 tokenizer；容量须按实际接口配置。
4. 自动事实记录保留来源消息；玩家可固定、纠正或忽略事实。状态由当前有效剧情重新计算；数组替换支持清空背包。已完成回复保存快照，未完成/失败回复不进入自动记忆。
5. 切换旧回复版本、编辑旧回复会截断当前分支的后续剧情，避免后续物品和事实污染。执行前会自动保存整条旧分支；可在「剧情分支」预览并恢复，详见下文。
6. 世界书支持常驻、启停、关键词任意匹配、回看深度、优先级、预算及前后插入位置；会话词条随存档保存。
7. 正则分为展示与请求两种范围；原始回复独立保留。隔离工作线程执行，超时退回原文。提供规则测试和恢复原始显示入口。显示规则应用于新回复，不会自动重绘全部旧消息。
8. 第一版声明式扩展清单支持版本、启停、附加提示词和正则；扩展设置随存档保存。导入默认关闭，不运行任意 JavaScript。
9. 角色卡导入保留原始数据，映射角色定义、示例、多开场和世界书，明确提示不兼容字段。部分酒馆显示正则可转换，转换后默认关闭。
10. 修复 SSE 网络分片与中文解码、流式错误、提前断线、长度截断和超时处理。支持停止生成、串行保存和保存失败重试，避免每个流式片段都写数据库。
11. 通用剧本状态面板只展示实际状态，新回复不会再附加默认好感度、默认物品或编造的后备选项。

## 数据与兼容边界

### 第二阶段：可恢复的剧情分支（2026-10-04）

- 重新生成、切换回复、编辑回复、编辑重发、撤回/删除，以及从旧消息续写前，先独立保存旧剧情。正常从末尾续写不额外建立分支。
- 「会话工作台 → 剧情分支」列出当前剧本的分支，可查看保存原因、时间、最后一条消息、自动/固定记忆和当时状态。
- 恢复时复制旧剧情到当前会话，恢复会话设置（含世界书、正则和扩展）并重算状态。恢复前的当前进度同样自动归档，原分支保持可再次恢复。
- 保存旧分支失败则中止改写，保留当前内容；保存期间阻止重复操作。若等待期间切换会话，不把旧操作应用到新会话。
- 分支使用独立的 `branch_` 存档 ID，来源与原因放在第一条消息的 `branchInfo` 中，无数据库迁移。普通会话列表及自动续接不选择分支原件。
- 当前采用完整快照，分支较多会增加存储空间。第三阶段补充来源层级、命名、搜索和回收站；不提供分支内容自动合并或永久清理。
- 验证：25 项会话测试、TypeScript 检查；独立模拟页面验收重新生成旧回复、预览及恢复完整后续剧情，不调用真实模型、不写正式数据库。

### 其他边界

- 会话设置保存在 history 第一条消息的 session 字段，利用现有 JSON 存档，无数据库迁移。旧存档自动使用默认配置，新生成回复使用通用格式；旧回复继续可读。
- 本机角色卡库存放于 localStorage，按用户 ID 分组；云端卡库单独按认证账号隔离，访客不能调用。上传与下载均由用户选择，不自动覆盖本机版本。下载不同内容时会先另存本机副本。PNG 图片本体不存入库，只读取角色卡元数据。
- 导入角色卡不会发布到公共广场；会话仍沿用现有后端保存接口。
- 备份包括剧本、历史和会话设置，不包括模型连接的 API 密钥。提示词检查只保存当前页面最近一次请求正文，刷新清空，不记录鉴权请求头。
- 已支持 V3 常用文本字段、昵称、外部素材映射、PNG tEXt/zTXt/iTXt，优先读取 ccv3。CHARX 内嵌资源、群聊、完整酒馆宏和 STscript/酒馆助手尚未兼容。未知扩展保留源数据但不执行。
- 摘要是带来源的事实摘录，检索采用英文词/中文双字匹配和最近消息排序，不额外调用模型或向量数据库。状态规则支持字段类型/范围及声明式事件，不是任意脚本游戏引擎。
- 为避免虚构状态，新会话不使用旧版固定道具盘及推演风格开关；玩法在会话工作台配置。旧模组代码尚未全部迁移到扩展接口。

## 扩展清单格式

```json
{
  "apiVersion": 1,
  "id": "concise-dialogue",
  "name": "简洁对白",
  "version": "1.0.0",
  "prompt": "对白保持简洁，每个人物使用自己的说话习惯。",
  "rules": []
}
```

规则字段：id、name、pattern、replacement、flags、scope（display 或 prompt）、enabled。扩展更新按同 ID 替换，并重新保持关闭状态。执行顺序为会话规则，然后按扩展列表顺序执行已启用扩展的规则。

### 第三阶段交付（2026-10-04）

1. **规则数据化**：新生成只使用通用会话引擎，移除聊天页中未使用的硬编码假回复模板。玩法页可将配置另存为私人剧本，包含世界书、正则、扩展、状态及视听规则；公共剧本也可通过 handbook.sessionDefaults 提供默认规则。历史回复的旧展示组件保留。
2. **记忆整理与找回**：每 12 条消息形成一段事实摘录；支持相关优先/最近优先、预算内旧事检索、试查、来源定位，提示词页可查看实际发送的事实。分支恢复后重新构建，排除已忽略事实和无效回复。
3. **状态与事件**：数值、文本、布尔、物品列表，初始值与数值范围；等于/大于等于/小于等于/包含条件，设置值与数值加减。条件读取执行前状态，每条完成回复执行一次，不递归。错误类型保留旧值，越界值限制范围，未定义字段不应用；原始回复仍保留。
4. **分支整理**：记录父分支及会话来源，树状缩进展示；命名、搜索、当前来源过滤、移入/移出回收站。移动至回收站不会删掉正文，恢复仍保留当前进度。旧分支缺少来源时作为独立起点显示。
5. **私人云端角色卡**：新增 private_cards 表及账号鉴权接口，记录完整卡片、版本号和删除标记；并发修改使用原子版本检查，冲突返回 409。读取及写入均从认证令牌取用户身份，不接受请求里的 user_id 作为归属。已验证 SQLite；当前 PostgreSQL 服务已完成建表及接口启动。尚未验证 MySQL。
6. **导入与预设**：V3 昵称/素材、压缩 PNG 元数据、酒馆静态 Chat Completion 系统提示词顺序、预算、温度/Top P；原卡可导出。独立酒馆显示正则支持 {{match}}。不支持的角色注入、动态位置、正则范围会提示并跳过；预设不导入连接密钥。
7. **高级世界书**：次关键词条件、概率、互斥组、组内权重/优先项、递归与排除递归，最多 4 层并受预算约束。酒馆精确深度位置、正则关键词、sticky/cooldown 等持续触发未实现。
8. **扩展管理**：内置对白风格、场景连贯检查、玩家自主行动；依赖最低版本、拓扑执行顺序、循环检测、参数、声明式配置迁移和上一个版本回退。缺失依赖不会执行。升级后默认关闭，保存检查后启用。
9. **视听联动**：按当前状态选择立绘/表情、背景与音乐；启用前不加载素材。音乐手动开始后可随场景切换，本机语音朗读最近完成回复；换会话或切换回复会停止朗读。没有可用本机语音包时明确提示，不连接第三方配音服务。

扩展可选字段示例：

```json
{
  "apiVersion": 1,
  "id": "dialogue-style",
  "name": "对白风格",
  "version": "2.0.0",
  "dependencies": [{ "id": "scene-continuity", "minVersion": "1.0.0" }],
  "defaults": { "style": "简洁自然" },
  "migrations": [{ "from": "1.0.0", "rename": { "tone": "style" } }],
  "hooks": {
    "beforePrompt": "对白风格：{{config.style}}。",
    "afterHistory": "给玩家留出回应空间。",
    "replyPrefix": "",
    "replySuffix": ""
  }
}
```

扩展只执行声明式内容。beforePrompt 进入背景指令，afterHistory 位于历史之后；replyPrefix/replySuffix 仅改变展示，随后执行显示正则。依赖扩展先于依赖者执行；同层按列表顺序。配置迁移只重命名声明的参数，不执行脚本；新版本只保留其 defaults 中声明的参数。

## 验证方法

在 web 目录运行 `npm run test:session`。测试直接编译实际 TypeScript 模块，覆盖预算、历史保留、宏、世界书、记忆、分支状态、导入、备份与流式读取。

当前有 50 项前端回归测试；运行 `python -m unittest discover -s tests -p test_private_cards_api.py` 验证 5 项卡库接口测试。接口测试使用临时 SQLite 数据库，不连接正式数据库。生产构建和类型检查通过；新增组件/模块的定向 lint 无错误（用户自定义图片使用原生 img，有两条性能建议）。

第三阶段页面验收：冒险状态示例触发疲惫事件；内置扩展安装/保存及其真实提示词位置；规则另存私人剧本；隔离测试账号上传、移入回收站、恢复（云端版本 1→2→3）。真实模型输出质量、不同设备上的语音包和用户提供的音视频地址未作外部服务验证。

独立页面验收：运行 `node tests/mock-server.cjs`，再在另一个终端设置 BACKEND_URL=http://127.0.0.1:5188、SITE_PASSWORD 为一个空格、NOVAL_BUILD_DIR=.next-session-check，然后运行 `npm run dev -- --port 3099 --hostname 127.0.0.1`。此配置仅供本机模拟验收，不用于真实部署。

验收页面为 `/chat/test_lighthouse`；模型设置使用模型名 local-test，Base URL 为 http://127.0.0.1:5188，API Key 留空。测试卡为 tests/lighthouse-card.json。模拟后端只保存内存数据，不读取正式数据库、不请求外部模型。

## 第四阶段首批交付：可复现试玩与记忆更正（2026-10-04）

- 首页「我的角色卡 → 添加灯塔冒险样例」会创建一个新的本机私人副本。样例包含成年人守塔人、开场、书房世界书、位置/物品/体力规则和明确的知识边界。不会修改已有剧本或发布公共卡片。
- 「会话工作台 → 试玩与诊断」检查缺失设定/开场、无法触发的世界书、未支持宏、无效状态约束和预算问题。诊断是配置检查，不是剧情质量评分。
- 独立试玩从剧本开场开始，每行一个行动，最多 8 轮，单轮超时 120 秒。可以使用固定灯塔样例，或当前剧本和工作台草稿。试玩和正式聊天共用提示词处理、输出解析、状态规则及显示扩展；不写入聊天存档。每轮会调用当前配置的模型并消耗额度。
- 可保留一次结果为对照 A，切换工作台页签调整草稿，再选择当前剧本重新试玩。固定灯塔样例始终使用样例自己的设置。工作台关闭或账号切换时中止请求；关闭会清空试玩结果，需提前导出。报告包含逐轮行动、请求、原回复、状态、实际模型名、采样参数、耗时和手工评语，不包含模型连接密钥或鉴权请求头。
- 对照需要保持剧本、行动、模型及采样条件一致。没有启用模型裁判；当前自动检测只有格式/状态规则警告和整段完全重复，人物越界、事实正确性与文笔需人工验收。不同模型服务、随机性和小样本仍可能影响结论。
- 自动记忆兼容旧字符串，并支持 `{ "key": "铜钥匙归属", "text": "铜钥匙由沈舟保管" }`。同一稳定事项的最新有效记录参与检索，旧值保留来源；切换分支后按该分支重新计算。模型若使用不同 key，系统不会自行猜测并合并，因此这不是通用语义冲突检测。
- 「记忆与状态 → 更正此事实 / 忽略此来源 / 撤销更正」绑定消息位置和回复内容标识。替换回复、删去来源后，对应更正不会误应用到其他回复。更正后的事实参与试查和正式提示词；不自动改写历史正文及状态快照。复用预设或另存玩法时清除私人更正。
- 新数据保留 `memory` 字符串视图，结构化事项另存 `memoryEntries`，兼容旧消息展示组件；会话设置新增 `memoryCorrections`，无数据库表结构变更。

## 手动剧情插图（2026-10-04）

进入「会话工作台 → 生图」填写独立的图片服务地址、模型和密钥并应用；然后点击通用聊天回复下的「生成本幕插图」，检查或修改描述后生成。支持剧情插画和无人物环境背景。生成不会阻塞继续聊天，完成后图片显示在原回复下，可放大、下载及再次生成。

访客图片存在本机浏览器，登录后会额外同步私人云端。工作台中的「我的插图画廊」可读取历史图片、重试上传或挂回对应回复。密钥仅保留在当前标签页内存，刷新后需要重填。切换或改写剧情时图片不会误挂到新回复；离开原会话后完成的图片可从画廊找回。

已经使用本地网关实际生成灯塔图片，并用该结果回放验证页面保存与刷新恢复。当前回归为 53 项会话测试和 8 项后端测试，生产构建通过。支持范围、部署存储要求和仍待完成的世界实体系统见 [后续开发计划](后续开发计划.md#5-第一版交付范围2026-10-04)。

## 回复截断与附加数据残片修复（2026-10-04）

- `finish_reason=length/max_tokens` 会标为达到输出上限；连接提前结束、取消/超时、内容过滤分别提示，不能仅凭末尾残片断定是后端截断。
- 流的最后一段正文与结束标记同时到达时，先保留正文再处理结束原因。出错时保存完整已接收原文，不再只保留最近一次刷新到页面的片段。
- 即使网关返回 `stop` 或 `[DONE]`，未闭合的 `<state>` / `<memory>` / `<options>` 也被判为附加数据未完成。正文隐藏这些协议片段，原文保留供诊断；普通正文中的方括号和引号不会被盲删。
- 未完成回复不更新状态、记忆或执行每轮事件，不提供依赖这些数据的行动选项和生图，也不进入后续模型上下文。旧存档中仍保留原文的残片也会在显示及上下文恢复时检查。
- 未完成提示提供「重新生成本幕」「调整回复预算」和原文/结束信息。重生成保留旧版本及分支，不自动反复重试或把不完整数据猜成完整数据。
- 「玩法 → 上下文与回复预算」说明正文与附加数据共用输出上限，并提供 4096 的草稿设置入口；需应用才生效。现有预算不自动提高。提示词要求为附加数据留余量，容量不足时缩短正文。

验证：58 项会话测试通过，类型检查和生产构建通过。使用中性灯塔模拟响应验收「正常结束标记但选项未闭合」、原文保留与刷新恢复；不重放用户截图中的剧情。没有新的真实模型请求。过去存档未记录的结束原因无法追溯确定，已丢失的文字也无法由解析器恢复。

### 8192 上限下仍提前结束：第二轮修复

只读取问题会话的诊断字段后确认，第 43、45、47 幕记录的请求上限均为 8192，网关均报告 `stop`；第 45 幕原文 726 字符且没有任何附加数据块，第 47 幕 934 字符且记忆块未闭合。8192 设置确已传入生成请求，现有记录不足以确定底层模型提前结束的原因，不能继续把所有异常归为输出上限过小。

- 新请求使用完整结束标记 `<reply_end/>`。仅在正文、附加数据和结束标记均通过检查后提交状态；缺少标记意味着「无法确认完整」，不等于已证明传输丢包。标记不显示在正文中。
- 旧回复没有这种约定，针对较长且没有自然句末、也没有完整附加数据的正文给出「可能未完成」提示；启发式可能误报，不据此永久重写旧存档。
- 新增「补全这条回复」：原始回复作为助手前缀随请求发送，模型仅续接缺失部分；结果合并到原消息位置，不新增玩家行动。原回复、旧版本及后续剧情先保留到分支。补全输入提前预留上下文空间，避免先塞满历史再加入前缀造成超限。
- 补全后重新解析完整原文，状态事件只在通过检查时应用一次。支持 JSON 中途断开及长段精确重复前缀去重；不猜测修复无效 JSON，不保证模型一定严格续接或不重复，仍不完整时保持提示。一次点击只请求一次，不自动无限重试。
- 原「接着写/补全剧情」改名「继续下一轮剧情」，明确它会新开一轮。服务明确返回内容过滤时不提供断点补全。
- 新诊断记录网关结束原因、请求上限、本次接收字符数、耗时、补全次数，以及服务提供时的输出/思考 Token 数。服务未提供的数据显示「未提供」，不估算为零，也不保存思考正文。

新增 5 项回归后共 66 项测试通过，类型检查及生产构建通过。隔离页面以 8192 预算模拟正文半句后 `stop`，确认能提示并补全回同一幕，保留 2 个版本。另用 `gemini-3.1-pro-high` 做一次中性灯塔真实请求：8192 上限，2874 字符，约 57.5 秒，`stop` 且完整结束标记存在；网关报告 completion_tokens=2166、reasoning_tokens=4840，这些字段按网关原样解释，不据此声称其内部预算规则已查明。没有重放用户原剧情，也没有修改模型服务的审核设置。
