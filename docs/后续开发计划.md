# 后续开发计划：世界状态持久化与剧情生图

记录日期：2026-10-04。

用户明确指出：不仅是背包，场景及场景里的物品、人物等也需要持续保存，不能只依赖模型从旧正文猜测；希望文本剧情能够配合生图 API 产生画面，并参考酒馆的做法。

状态：已实现第一版手动生图；世界实体持久化、自动生图与人物参考图仍待开发。以下清单保留完整目标，不表示全部交付。

## 1. 高优先级：世界状态持久化

当前实现：会话消息保存状态、结构化记忆和来源，程序恢复最新状态并选择事实进入请求。尚无独立、完整的场景/人物/物品实体记录。

目标：已发生的世界变化由程序持久保存，模型根据当前有效世界状态继续剧情。

- 场景：稳定 ID、名称、可观察描述、连接地点、时间/天气及必要的环境变化。
- 人物：稳定 ID、当前位置、当前行动、与其他人物已确认的关系、各自已知的信息。未知信息与未发生事件不能自动变为事实。
- 物品：稳定 ID、数量、状态及唯一归属位置；位置可为玩家、NPC、场景或场景中的容器。
- 事件：来源会话、分支、消息与回复版本；记录已验证的变化，必要时保存快照。
- 模型在同一次剧情回复中提出结构化更新，程序验证后提交；默认不额外调用一次模型去重建世界。没有有效更新时保留旧值，并提示缺失或矛盾，不能无声清空。
- 更新需原子应用，拒绝不存在的实体引用、负数量及物品同时属于多个位置等冲突。
- 切换回复、撤回、删除或恢复分支时，从相应分支的事件/快照恢复，不能串用废弃分支的数据。
- 玩家可检查并纠正世界状态，修正有来源记录；不仅修改提示词中的记忆文本。
- 每轮发送当前场景及相关实体摘要，完整世界存于项目自身数据中；避免每轮把整个世界送给模型。
- 旧存档逐步兼容，不未经检查地把历史正文中的所有描述视为已确认事实。

验收场景：钥匙由 NPC 持有 → 放在桌上 → 玩家取得 → 放进书房抽屉 → 玩家离开 → 返回后仍在抽屉；刷新、重新登录及分支恢复结果一致；省略早期正文后仍能正确读取归属。

## 2. 剧情生图调研结论

SillyTavern 支持按角色、上一条消息、故事或背景生成图片，可手动触发及通过工具调用触发；多数模式会额外调用文字模型整理绘图提示词，原文和自由提示词模式可跳过。其 ComfyUI 接入使用可替换参数的工作流。[官方生图文档](https://docs.sillytavern.app/extensions/stable-diffusion/)

酒馆的角色表情功能还可切换预先准备的立绘，不等同于每次重新生图。[官方表情文档](https://docs.sillytavern.app/extensions/expression-images/)

ComfyUI 提供工作流提交、队列、历史和图像访问等接口，适合后续较复杂的本地工作流接入。[官方服务接口](https://docs.comfy.org/development/comfyui-server/comms_routes)

当前项目保留按状态显示已配置背景、立绘等素材，另已接入手动生图、当前标签页任务管理、私人图片保存与画廊。

2026-10-04 已实测用户本地网关 `/v1/images/generations`，`gemini-3.1-flash-image` 返回成功，响应为 `data[].b64_json`，实际图片为 JPEG。测试内容为无人物灯塔水彩场景。模型标识由网关提供，不代表已独立核验底层供应商；其他图片协议仍需单独适配。

## 3. 建议实现顺序

### 第一步：手动为回复生成插图

- 生图服务设置与文字模型分开：地址、模型、凭据引用、尺寸、画风及供应商支持的其他选项。
- 优先验证用户现有本地网关；适配器统一处理同步图片响应或异步任务。其他后端（例如 ComfyUI）按需逐个接入。
- 回复旁增加“生成插图”，支持“当前画面 / 场景背景 / 指定人物”以及绘图描述预览与编辑。
- 从所选回复对应的世界快照、可见人物和画面重点构建提示词；旧消息生图不能误用最新场景状态。
- 第一版可以直接用模板拼装已确认视觉信息；需要更自然的构图描述时，可选额外文字模型整理。明确一次操作实际涉及哪些请求。
- 图片生成异步执行，文字回复和继续聊天不等待图片；展示生成中、完成、失败、取消与重试。
- 生成结果绑定会话、分支和消息版本。切换分支后迟到的结果仍属于原消息，不能贴到当前分支。
- 账户隔离地保存图片文件/对象，消息只引用素材 ID；记录提示词、模型和参数。不能只依赖会过期的远程图片 URL，也不把大段 Base64 放进每次发送的聊天历史。
- 提供查看大图、下载、重新生成与历史版本。图片属于剧情插画，不把画面里模型自行画出的物品反向写入世界事实。

### 第二步：按剧情触发与复用

- 用户可选关闭、手动、切换场景时、关键事件时或每次回复后生图；默认手动。
- 场景及视觉状态未发生变化时复用已有图片；按人物、地点、服装、时间、画风等视觉条件生成缓存标识。
- 自动模式设置频率上限、同一消息去重和任务并发限制，避免重复请求；失败不触发无限重试。
- 背景、角色立绘、剧情插画分别管理，普通对白不需要每轮重绘整幅画面。

### 第三步：人物和场景一致性

- 保存角色外观档案、当前服装和场景视觉描述；固定画风。
- 按服务能力使用参考图、图生图或 LoRA 等手段；不承诺仅靠相同文字或固定 seed 就能让人物始终一致。
- 引入 ComfyUI 工作流、表情素材切换和专属画廊。

## 4. 验收重点

1. 中性灯塔剧情能够在指定回复下生成插图，刷新后仍可读取。
2. 使用的是所选回复的场景、人物和物品归属，而非废弃分支或后续消息。
3. 超时、失败、取消、重试、页面切换不会损坏聊天或重复挂载图片。
4. 场景不变时可复用；视觉条件改变时能生成新版本。
5. 凭据不进入角色卡、提示词、存档导出及普通日志；图片和世界数据按账户授权读取。
6. 同一模型下对人物一致性和生成耗时进行真实验收，记录局限。

## 5. 第一版交付范围（2026-10-04）

- 会话工作台 → 生图：独立服务地址、模型、尺寸、统一画风。密钥仅留在当前标签页内存，刷新或账号切换后清除；其他设置仅存在本机。
- 通用会话回复下“生成本幕插图”：剧情插画 / 无人物环境背景，预览并编辑绘图描述。直接从所选回复及其历史状态、有效记忆拼装，不额外请求文字模型。
- 同一账号同一标签页一次只运行一个生图任务；可继续聊天，可取消，180 秒超时。取消不能保证上游服务停止计费或计算。
- 图片先写入浏览器 IndexedDB；已登录时再上传私人云端，云端失败保留本机结果并可从画廊重传。账户访问由后端验证，不接受请求体中的身份。
- 图片绑定稳定回复版本标识；迟到结果只匹配原回复或其备选版本。切到不包含原回复的分支时，结果保留在画廊，恢复原分支后可手动挂回。
- 查看大图、下载、再次生成及此前版本；图片文件与聊天分开，存档仅保存引用与参数。生成画面不会反向修改世界事实。
- 生产构建、53 项会话测试和 8 项后端测试通过；浏览器使用真实生成图片的隔离回放验证展示和存档恢复，回放不代表再次调用真实模型。

限制：第一版仅支持同步 Images API 的 Base64 响应，单图上限 16 MB；暂不支持仅 URL 返回、ComfyUI 异步工作流、人物参考图、自动触发或图片复用。尚未实现图片删除、容量配额、后台任务跨刷新恢复；生成期间刷新会中断接收。浏览器数据清理会丢失本机图片，建议下载备份或上传私人云端。云端部署须把 `data/generated-images` 作为持久目录并与数据库一起备份。

世界场景 / NPC / 物品实体及事件持久化仍是下一阶段重点，现有图片描述使用会话状态与记忆，尚不声称具备完整世界数据库。

### 生图失败诊断补充

用户反馈角色卡生图失败后，项目日志确认近期图片请求返回 HTTP 502（约 4–11 秒），但旧界面统一显示「检查模型、地址和密钥」，未保留上游错误分类。使用同一网关与模型进行新的无人物灯塔测试，HTTP 200 并返回 Base64 图片；这只能证明该次中性请求成功，不能反推此前请求一定因内容拒绝。

已区分上游拒绝、鉴权/权限、额度不足、限流、模型不支持、参数错误、超时、没有可用图片，以及项目到网关的连接失败。代理日志仅记录阶段、HTTP 状态和错误类别，不记录凭据或故事原文。错误响应最多读取 32 KB，界面使用固定说明而非直接展示可能回显密钥的服务端正文。未识别的 502 明确提示查看网关日志，不自动修改角色卡、过滤词或反复请求。

新增分类与隐私/响应大小测试后，会话测试共 61 项通过。此前三次失败的上游原因无法从旧日志恢复，需要新的失败响应或网关自身日志确认。
