## 二、第一篇核心精要：AI风月剧本与提示词工程法则

### 1. 作品的双层结构体系
- **门面层（给玩家看）**：
  - 名称（抓人悬念/矛盾对立）、头像、简介、详细介绍（HTML富文本沙箱）、BGM与开场白；
  - 作用：决定首跳率与转化率，必须前3秒传达出“核心卖点”与“禁忌/冲突张力”。
- **核心层（给大模型看）**：
  - System Prompt（设定主体）、前置词、后置词、世界书；
  - 作用：决定对话留存与长效稳定性。

### 2. 角色卡 4 维画像模型（拒绝空洞形容词堆砌）
官方手册强调，AI 无法理解“性格温柔中带着倔强”这种虚词，必须转化为：
1. **外貌与装束**：具象清单（如泪痣位置、发带细节、随剧情阶段变化的服饰）；
2. **性格情境分支（条件响应机）**：
   - 格式：`【当 [外部输入/玩家行为] 时】：[角色的微表情/微动作] + [台词倾向/肢体反应]`；
3. **因果链背景（事件 → 影响）**：
   - 解释角色“为什么会变成这样”（例如：十三岁被推开导致病理性共生依恋）；
4. **语言习惯与口癖**：
   - 专用称谓、标点偏好（如频繁使用省略号或短促反问）、固定动作口癖。

### 3. AIRP 上下文底层逻辑与注意力分布
- **一切皆上下文**：大模型并不知道什么是“前置”或“后置”，平台后台是将所有模块拼接成一个巨大 Prompt 发送。
- **首因效应与末尾增强效应**：
  - **最前面（System开头）**：放最核心的人设身份与绝对禁止项（建立基底印象）；
  - **最后面（后置词/最新输入）**：AI注意力最高处，放置输出格式规范、状态栏模板与当前幕核心行动诱导；
  - **中间区**：动态挂载的世界书条目与历史对话。

## 三、第二篇核心精要：正则替换与皮肤代码的流水线美学

第二篇以极通俗的大白话阐述了前端美化流水线：**“正则贴记号，CSS 画样子”**。

### 1. 正则替换的 4 要素与唯一高级符
在平台中新建正则规则时，永远牢记：
- **影响范围**：必须选择 **`AI输出`（scope: 10）**；
- **核心符号 `$1`**：配合捕获组 `( )`，原样保留匹配到的内部文本。

### 2. 状态栏与推荐选项的标准正则模板
```json
[
  {
    "scope": 10,
    "title": "<details>",
    "is_enable": true,
    "match_regex": "<details>",
    "replace_text": "<details class=\"custom-panel\">"
  },
  {
    "scope": 10,
    "title": "<summary>",
    "is_enable": true,
    "match_regex": "<summary>",
    "replace_text": "<summary class=\"custom-summary\">"
  },
  {
    "scope": 10,
    "title": "suggested_questions",
    "is_enable": true,
    "match_regex": "(<suggested_questions>[\\s\\S]*?</suggested_questions>)",
    "replace_text": "<div class=\"custom-suggest\">$1</div>"
  }
]
```

### 3. 平台三大实战排坑要点
1. **推荐选项多行挤成一行**：
   - 原因：平台默认解析可能忽略换行。
   - 解决方案：在 CSS 外框上添加 `white-space: pre-line;`。
2. **样式互相污染（命名空间隔离）**：
   - 严禁全局覆盖通用的 `.panel`，务必为每个剧本或角色加上独有前缀（如 `yuzuki-panel`、`yuzuki-summary`）。
3. **两个完全不同的 HTML 运行环境**：
   - **详细介绍页**：位于受限沙箱 iframe，不支持 JS，仅支持纯 HTML + 内置 CSS；
   - **聊天游玩阶段**：支持执行脚本与交互表单。
